# 双图创意融合生物

## 当前策略与边界

当前新任务使用 `creative_fusion`，不再固定换头。服务端的 `fusion_policy()`
要求多模态图像模型先观察可见特征，再比较三个融合方向，最终只输出一张角色参考图：

1. 人脸辨识优先：保留脸型、眉眼、鼻口比例、发型、神态，而非通用娃娃脸。
   两图都有人时优先 A 的主要人物；仅 B 有人时反向分配；无人脸时保留主体标志特征。
2. 保留另一张图的夸张姿势、重心、手势、四肢朝向、轮廓和色块，不统一改为站姿。
3. 比较姿势反差型、Q 版服装融入型、轮廓重组型，先保脸和姿势，再追求喜剧反差与猎奇感。
4. 复杂衣服只留下主色、领口、外套轮廓及一两个标志配饰，不还原细字、证件和手机。
5. 单个完整 Q 版角色，连接清楚、配饰附着、四肢完整，纯背景，无拼图或分析文字。

每个任务固定一个同等方案下的创意侧重点，保存在 `fusion_policy` 中，
连同版本、分析方式、图像及建模提示词一起落盘，重试不重选。
这个侧重点是多样性提示，不是根据图片计算出的评分。

**能力边界**：观察和选优在图像生成请求内由模型执行。当前没有独立视觉分析 API、
特征框、分割遮罩、结构化识别报告、实际生成的三张候选图或可验证的候选评分。
代码测试只能验证规则传递和流程，不能证明模型实际比较了候选，也不能保证每次“最有节目效果”。
需要可审计分析时，应另接返回结构化结果的视觉模型，不能把提示词当作识别结果。

## 游戏入口

启动 `python serve.py 8765` 或 `start.bat`。走到一座没有亲代、没有进行中任务的太空舱前，
按 E 或点击「创意融合」。选择图片 A 作为人物参考、图片 B 作为姿势与造型参考，
点击「上传并生成 3D 生物」后才会上传并创建收费任务。

支持 PNG、JPEG、WebP，每张上限 10 MB。选图界面有预览，可取消，不会在选图时调用 Tripo。
提交后会先执行“融合图生成”，再执行“3D 建模”，界面显示两个阶段的上传、排队、生成、下载进度。模型加载成功后直接出现在舱内，
按 E 或「收下后代」领取，优先进弹夹，其次进背包。库存满时仍留在舱内。
照片路径无需亲代，不播放需要两个亲代的融合演出。原来的双亲繁衍流程保持不变。
单文件以 `file://` 打开时是离线演示，不提供照片生成；通过本地服务打开才可使用。

## 接口和数据

- 本地接口仍为 `POST /api/tripo/jobs`，新模式使用 `mode: "creative_fusion"` 和
  `images: {a, b}`。两项是图片 data URL，不再固定为头与身体。
- 服务端校验格式、文件头、大小和任务 ID，将照片存放在私有 `.tripo/<id>/`，
  任务日志保存引用顺序、格式、SHA-256 及创作规则。静态服务器不会暴露原图或密钥。
- 调用 Tripo `/upload/sts` 上传 A、B 两张照片，随后向 `/task` 提交多图参考的图像生成任务。
  提示词用 `[1]` 指向 A、`[2]` 指向 B，模型依照可见内容选择融合方案。
- 下载合成参考图后再次上传，向 `/task` 提交 `image_to_model`，最终 3D 模型使用合成图作为唯一建模输入。
  因此模型链路是“两图观察与融合 → 合成图 → 3D 模型”，而不是把 A、B 当作同一个生物的两个视角。
- 使用现有 `P1-20260311` 和 3000 面上限。照片模型等比缩放到体型 A 的包围盒内，
  不沿各轴拉伸；原基因生成模型的制式化规则不变。
- 照片外观不代表识别出了遗传基因。目前为照片生物分配合法的默认 36 位游戏基因，
  供后续繁衍使用，记录 `generationSource: "creative_fusion"`，亲代列表为空。
- 历史 `head_swap` 和 `multiview` 任务继续兼容，不改写旧任务。

官方接口依据见 Tripo 的 Generation、Upload 和 Task 文档。

## 失败恢复

同一任务 ID 不允许替换照片、方向或基因，重复点击不会重复创建收费任务。
上传失败尚未创建生成任务，可手动重试；提交结果未知时必须先核对 Tripo 控制台。
第二阶段即使已有图像任务 ID，3D 提交未知时仍需核对确认；服务重启后也不会自动重提。
已知远程任务 ID 的中断只继续查询、下载，不重新生成。照片保留在本地私有任务目录中用于恢复。
此功能沿用现有页面会话状态：刷新页面不会自动恢复舱位或背包；服务端任务记录仍保留。

## 上传故障排查

上传错误会显示失败参考图（A、B 或融合参考图，旧模式为对应视角）及安全的诊断信息：
超时、连接中断、鉴权错误、格式拒绝或缺少上传凭证。任务日志和查询接口中的
`upload_error` 保存视角、错误分类及可用的 HTTP / Tripo 错误码，不保存密钥或上游原始响应。
手动重试会将旧诊断保留在历史记录中，成功后清空当前错误。
只完成上传不代表已经创建 3D 生成任务；上传失败仍可重试，不会重复提交生成任务。

2026-09-24 排查：最近两次失败的旧日志仅有通用上传错误，无法追溯具体根因。
此前真实 JPG/PNG 样例属于旧换头模式：上传、头身合成、3D 建模、GLB 下载和面数检查成功，
实际结果为 2977 个三角面。这不代表当前创意融合策略已完成真实视觉验收。
当前策略尚未提交新的付费任务，人脸相似度、姿势保留和服装简化效果待验收。
