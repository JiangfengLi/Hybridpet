# Tripo 后代模型生成

当前 HTTP 运行方式已使用真实 Tripo 模型。双击 `start.bat`，或运行 `python serve.py 8766` 后访问 `http://127.0.0.1:8766/`。直接双击单文件 HTML 是离线演示，会明确标示占位模型；通过本地服务打开单文件 HTML 则可生成真实模型。

## 游戏规则与流程

1. 两只亲代投入太空舱后保持开放，玩家确认结合才开始密封；沿用 36 位基因：逐位 50% 继承，每个可变位的突变率随爱心进度从 5% 线性提升到 25%。确认结合时固定随机计划，先辐射；确认当前进度或达到 100% 后才定稿基因并提交一次生成。查询、下载、暂停和重播都不重抽，见 `RADIATION-MUTATION.md`。
2. 将基因转成单个宠物的模型描述，包含主体、体型比例、颜色、质感、有的部件和实际数量的附属物。不表达的部件保留遗传值，不加入正向描述；服务端根据有无位生成反向提示词，约束无眼、无翅膀等特征。
3. 孕育直接使用 Tripo 返回的生成百分比，不再设置 90 秒等待门槛。API 达到 100% 后仍需模型下载并在浏览器解析成功，才能进入出生演出；下载和载入阶段分别显示状态。离线单文件演示不调用 API，明确标示为“离线演示”进度。
4. 生成使用 `P1-20260311`，显式请求 `face_limit=3000`。完整 GLB 下载到本地后，统计活动场景中所有节点实例与网格图元的三角面数；只有不超过 3000 面的模型能交给游戏。超限或文件不完整会显示错误，不以占位球伪装完成。
5. 完整模型使用统一包围盒逐轴缩放至基因体型 A–F，底面归零。所有网格、材质、UV、贴图保留，附属物相对位置保留；碰撞圆柱从最终模型实测。
6. 模型就绪后进入迪斯科融合舞台，直接使用舱内两只亲代，不再显示模型选择或旧旋转碰撞/DNA 播片。按空格累计进度，松手衰减；进度满后展示本次生成的后代，并播放原有 `birth-mama.wav` 音效一次。出生演出和领取使用同一个生成模型。后代有独立物种 ID、模型任务 ID、基因、提示词和亲代物种记录，能捕获、发射、移动和继续繁殖。速度仍取亲代平均。

AI 生成仍有解释空间，不能保证每个零件逐项精确对应。真实样例保持了白色圆润主体，但额外生成了眼睛与小肢体；检查画面后已为后续生成加入反向提示词约束。体型尺寸、基因继承和面数门槛由程序确定。

## 服务端配置

密钥查找顺序：`TRIPO_API_KEY`、`TRIPO_API_KEY_FILE`、项目中的 `.secrets/tripo.key`。本机密钥已配置。网页、单文件构建、任务 JSON 和日志不包含 API Key。

`serve.py` 仅绑定本机回环地址。付费提交需要同源请求与服务端发放的请求令牌；静态文件白名单拒绝访问私有目录、Python 源文件和目录列表。`.secrets/`、`.tripo/`、生成记录及截图已加入 `.gitignore`。

每轮孕育以唯一 ID 写入 `.tripo/<id>.json`，模型缓存在 `.tripo/<id>/model.glb`。同一 ID 重复请求只返回原任务。保存结果后不再依赖 Tripo 的短期下载链接。

提交被明确拒绝时，界面显示密钥、积分、限流、参数等具体原因以及错误码；修正原因后点击“重试提交”，使用相同孕育编号和基因再次提交。HTTP 状态码、业务错误码和请求追踪编号保存在任务记录的 `submission_error` 中，不记录原始响应或密钥。

提交结果未知（包括旧版 `unconfirmed` 记录）时，点击“核对后重试”会要求先在 Tripo 控制台确认没有创建任务。只有明确确认后才允许重新提交；取消则保留原记录。若控制台已有任务，不应确认重提。每次人工重试保留之前的错误记录。

出现网络/下载故障时，可点击“继续查询 / 加载”，只查询或下载原任务。若提交响应丢失且没有取得远程 task_id，系统不自动重复提交；需要在 Tripo 控制台核对。服务器重启后也只恢复已知任务的查询。点击“结束本次孕育”释放亲代操作；已经提交的远程任务不会因此退款或取消，完成后仍保留缓存。

游戏整体仍无存档：刷新页面不会保留世界中的宠物、亲代槽位或当前交互状态。已下载模型和任务资料留在 `.tripo/`，但不会自动恢复到背包。本轮没有扩展为游戏存档系统。

## 验证与复现

```powershell
node test/run.mjs
python -m unittest discover -s test -p test_tripo_service.py
```

常规测试不调用付费 API。覆盖去重、提交结果不明、断线查询恢复、重新下载、密钥隔离、多网格归一化、模型完成门槛、领取、继续繁衍及过期异步响应。

本机真实验证只提交了一次：task_id `605b3523-70d1-45bb-8cce-ff5e04b9c913`，基因来自游戏的 `inheritGenome`，结果为白色胶质球形宠物，三角面 **2829**，消耗 **40 积分**。确切基因、提示词、局部孕育 ID 保存在 `.tripo/live-fixture.json`。

`test/tripo-browser.mjs` 是显式运行的浏览器验收脚本：只重放该 fixture 的本地 ID，不重新生成。它在浏览器测试响应中注入已验证的基因与 ID，验证真实 GLB/贴图加载、完整演出与领取，不修改发行版。Node fixture 只生成基因，不提交任务；`test/tripo-live.py --submit` 才提交，重复调用同一 fixture 不重复生成。不要为了查询进度重新生成 fixture。

## 文件分工

- `tripo_service.py`：任务日志、远程提交/查询、下载、GLB 检查。
- `tripo_client.py`：随项目分发的 tripo-3d 技能标准库客户端快照，负责鉴权、HTTP 错误与下载；无需依赖用户的技能安装路径。
- `tripo-runtime.mjs`：浏览器进度查询、Meshopt 解码、完整模型归一化、独立实例。
- `index.html`：基因、孕育计时、后代实体与服务接线。
- `chamber-system.mjs`：生成进度、恢复/结束操作、出生演出和领取。
- `vendor/meshopt_decoder.module.js`：meshoptimizer v0.25，MIT，许可证见同目录 `meshoptimizer-LICENSE.md`。

接口依据：[Tripo P1 文生模型](https://docs.tripo3d.ai/model-generation/text-to-model-p1-20260311.html)、[任务查询](https://docs.tripo3d.ai/task-query/get-your-task-result.html)。
