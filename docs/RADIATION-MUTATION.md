# 爱心辐射与基因突变

## 概率

本轮每个可突变基因位的概率：

```text
p = 0.05 + 0.20 * radiation
radiation = 爱心条的实际进度，范围 0 到 1
```

| 爱心进度 | 每位突变概率 |
| --- | --- |
| 0% | 5% |
| 25% | 10% |
| 50% | 15% |
| 75% | 20% |
| 100% | 25% |

连续线性插值，不分档，不依赖显示百分比的取整。25% 是每个可变位的概率，不代表后代必有 25% 的基因改变，也不是整只后代只抽一次。

沿用现有 36 位基因表：每位先等概率选择一个亲代；如果发生突变，则从该位除继承值外的其他选项等概率选择。只有一个选项的位点不突变。

## 本轮流程

1. 投入两只亲代，合舱。为每个基因位固定继承选择、突变随机数及备用突变值，暂不调用 Tripo。
2. 密封后进入爱心辐射阶段。按 E 领取枪，命中后增加进度并更新候选基因；HUD 显示当前突变概率，不公开具体基因或突变位点。
3. 装备枪且在对应舱旁时，再按 E 确认当前进度；也可点击 HUD 的“确认生成”，不领取枪直接按 5% 开始。
4. 达到 100% 自动确认。确认后锁定概率、基因和提示词，清除在途弹药，再提交一次 Tripo 生成。后续射击不再增加本轮进度或修改基因。
5. 模型生成、下载和载入仍使用真实 API 进度。重试沿用同一请求 ID 与基因，不重新抽样、不另建付费任务。
6. 离线演示同样先确认，再开始原有演示进度。
7. 出生完成后该舱进度清零，新一轮回到 5%。后代及出生结果保留本轮实际采用的突变率和辐射进度。

不会在模型已经提交后只修改基因标签：交给 Tripo 的基因、提示词、尺寸规范与出生使用的基因是同一份。

## 状态与接口

- `mutation-rate.mjs`：纯概率映射、随机计划、基因解析；每轮只抽一次随机数，反复命中不会增加抽奖次数。
- `breeding.pairs[p]`：新增 `inheritancePlan`、`radiation`、`mutationRate`、`genesLocked`。
- 生命周期：`idle -> irradiating -> running -> ready -> idle`。
- `updateMateRadiation(p,value)`：仅允许未锁定的辐射阶段更新，进度只增不减。
- `confirmMateRadiation(p,value)`：定稿并进入生成，重复调用无效。
- `chamberSystem.confirmRadiation()`：确认当前瞄准或邻近、可确认的舱。
- `__chamberStatus(id).mutation`：`{rate, locked}`，和爱心条同属该舱。
- `child.mutationRate` / `child.radiationProgress`：出生时采用的数值，不成为下一代自动继承的加成。
- `chamberWater` 既有事件、阈值与接口名称保持兼容。

各舱使用独立随机计划和概率；一座舱的射击、确认、失败、重试或清零不会改变其他舱。

## 测试状态

新增 `test/mutation-rate.mjs`，覆盖线性映射、上下限、固定随机数、单选位点、三舱隔离、确认后只提交一次、重试和过期响应。同步更新旧流程用例。

按用户之前“停止验证”的要求，本轮不运行测试、浏览器验证或付费 API；仅生成单文件包及执行构建器自带资源检查。测试代码不等于已经通过验收。
